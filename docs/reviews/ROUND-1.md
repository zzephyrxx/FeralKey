# FeralKey 第一轮代码审查

日期：2026-10-30。审查者：独立 reviewer agent。参照初始备份 `af3cb3a` 及品牌变更中的工作树；下面行号对应修复前版本。

范围：设备写入边界、异常处理、配置导入、子进程、退出/重新连接、构建与打包。未打开或写入实体键盘，未调用真实账号接口。第一轮不是最终安全通过结论，修复后另做第二轮复核。

## 需要修复

### R1 · P1 · 外部 URL 可以无确认、无限频率触发设备写入

- 位置：`Sources/LabModel.swift:246–250`、`:119–134`。
- 条件：已接受风险并在当前运行中成功应用基础灯效。
- 复现路径：外部应用重复打开 `feralkey://notify`。`handleURL` 直接调用 `notify`，每次都发送灯效报告，并取消上次的恢复任务。没有入口操作确认、可撤销的外部写入授权或节流。
- 影响：外部调用方可以连续控制灯光并推迟恢复。已有资料未确认该命令是否写入持久存储，所以频繁调用尤其不应默认放行。
- 建议：外部通知入口先呈现本次操作确认；所有通知来源设置统一冷却，避免重复发送。不得将“接受一次研究须知”视为接受任意外部调用方的无限写入。
- 验证要求：模拟传输下，URL 处理后、确认前为 0 次写入；取消为 0；确认后一次；冷却内再次确认不产生额外写入。

### R2 · P1 · 重连后旧通知回调可以写入新连接

- 位置：`Sources/LabModel.swift:95–96`、`:128–134`、`:137–140`。
- 复现路径：在连接 A 应用基础灯效 → 触发通知 → 4 秒内重新连接（或改接同型号 B）→ 原来的延迟任务仍调用当前 `hid.send`，将 A 的基础设置写到新连接。`connect` 没有取消旧定时写入，也没有撤销 `appliedLight`。
- 影响：旧连接的授权上下文、恢复设置和计时器跨到新设备。重连后即使用户尚未重新应用基础灯效，通知仍可能可用。
- 建议：每次连接代次变化、设备发送失败/关闭均撤销本连接的基础灯效状态、取消延迟通知/专注写入；回调捕获并检查连接代次。旧回调必须无法对新传输发送。
- 验证要求：模拟连接 A 通知后重连 B，推进恢复时钟，B 收到 0 次旧回调报告；必须重新手动应用基础灯效后才能通知。

### R3 · P2 · 配置导入绕过支持范围，并且无文件大小限制

- 位置：`Sources/Protocol.swift:82–88`；`Sources/LabModel.swift:77`、`:182–189`。
- 复现：纯 Swift 测试调用 `RKCodec.keymap(overrides: [65: 0x080600])` 可改写 Fn；`overrides: [0: UInt32.max]` 可写入未知码，两者都成功生成 9 个报告并通过 `validateTransaction`。没有发送设备报告。
- 影响：导入文件可越过界面对 Fn 的禁改规则、给键盘发送未经研究的映射值。所有文件在主线程一次读取，超大 JSON 还会导致明显卡顿或内存耗尽。持久化配置载入也没有统一验证。
- 建议：统一配置验证用于导入、偏好载入和最后生成报告；拒绝 Fn 覆盖及不在明确支持集合中的映射值。读取文件前和读取过程中限制大小，不合格配置保持现有有效状态并报错。
- 验证要求：合法现有预设保持兼容；Fn/未知码/非法版本/无效灯光/过大文件在任何发送前拒绝，损坏持久化配置不会进入活动模型。

### R4 · P2 · 自动发现 Codex 会接受相对 PATH 项

- 位置：`Sources/CodexClient.swift:25–29`。
- 条件：启动环境 PATH 含 `.` 或其他相对目录，当前项目或启动目录含名为 `codex` 的可执行文件。
- 影响：本应自动连接已安装 Codex 的流程会执行当前目录中的同名程序；这不是显式文件选择产生的信任决定。
- 建议：自动候选只使用绝对 PATH 目录；拒绝目录等非普通文件，并将明确指定的路径也限制为绝对可执行文件。符号链接到受支持的安装位置可保留兼容。
- 验证要求：临时相对 PATH 候选不被选择；明确的有效绝对文件正常；目录或非执行文件拒绝。

### R5 · P2 · 资源缺失或损坏直接终止应用

- 位置：`Sources/LabModel.swift:67–71`。
- 复现：移除或破坏应用资源中的布局/键码 JSON，再启动即触发 `fatalError`，用户无法进入可解释的错误界面。
- 影响：分发包损坏、资源加载失败被处理成崩溃。若改为降级，必须同时防止空布局生成全零键盘映射。
- 建议：记录启动失败并显示说明；资源无效时禁止设备配置，允许查看错误及退出。不要以可写空布局静默恢复。
- 验证要求：缺失与非法 JSON 都不会崩溃，并且所有相关设备写入入口不可用、模拟传输收到 0 次发送。

## 可后续优化

- `Main.swift` 的每个键帽单独访问 `model.quotaColors`，每次会重新生成整套颜色字典；可在键盘视图的一次更新中计算一次再传入。该项是分配量优化，不作为安全阻断项。
- `KeyboardHID.send` 为主线程同步 I/O，慢设备会阻塞界面；后续可引入串行设备队列与明确取消/超时策略，但需要保持完整事务顺序和连接代次检查。
- 构建与打包脚本有明确源目录白名单、无账户文件打包路径；目前未确认额外阻断问题。正式分发前仍需签名、公证以及实物验证。

## 正向确认

- 设备打开严格匹配编号、USB 传输、用途和 Feature 大小，多个匹配拒绝打开。
- 完整事务在第一包发送前验证；未暴露固件、启动加载器和任意原始命令入口。
- 额度数据缺失、过期、跨重置点或请求失败时不允许同步；演示数据不允许写实体。
- Codex 错误不直接显示原始服务文本，子进程具备超时、取消和关闭处理；还需结合后续修复再次验证。
