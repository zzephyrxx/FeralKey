# 0.5 验证记录 · 2026-10-30

## 已执行

- `scripts/test.sh`：协议检查、768 项额度/报告/发现检查、Codex stdio 异常与取消检查、模型安全检查，以及 390 项组合键/通知图案/音量/刷新/调色板/区域检查通过。HID 全部使用模拟传输。
- 新模型场景：固定额度不会被基础颜色或亮度零覆盖，并保持休眠关闭请求；通知区待机熄灭；通知只改自己的区域；通知期间成功更新额度后，四秒恢复不会回退额度；重叠键优先留给额度；关闭隔离后跑马灯使用固件模式 9。
- `scripts/test-auto-refresh.sh`：真实等待 30 秒，本地模拟 Codex 自动读取两次后停止，无账号或设备访问。
- `tests/PackagingTests.py`：隔离的无 Git 源码副本成功构建；源码/应用包排除递归假凭据与外部链接；旧资源不会混入；构建失败保留上个有效签名应用。
- 明亮额度页、深灰通知页离线渲染检查：两个选色器、固定选项、横幅监听入口与区域独立设置正常显示。演示模式不连接设备，也不启动系统通知监听。

测试初次因新增基础亮度处理而触发旧测试中“默认亮度等于原始 RGB”的断言；测试改为明确使用满亮度，并另增基础亮度零仍保留额度的场景，之后全套通过。

- 未向实体键盘发送任何配置；本轮没有验证 RK98 的模式、颜色、分区或恢复实物效果。
- 未为应用授予辅助功能权限，未读取本机通知中心界面，未实际发送测试横幅，未验证微信联动。横幅去重使用本地集合测试；真正的系统结构识别需要用户按功能说明操作。
