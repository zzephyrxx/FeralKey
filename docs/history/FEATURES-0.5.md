# FeralKey 0.5 · Agent额度灯与分区通知

## 额度颜色与固定显示

侧栏入口改为「Agent额度灯」，数据源当前仍为 Codex。五小时与每周可以分别选色，颜色保存在本机。默认保留 ≤25% 橙色、≤10% 红色警示，也可关闭警示并始终使用自选颜色。修改颜色先更新预览，下次同步才写入键盘。

连接键盘并读取真实额度后，可开启「固定额度区，不允许其他灯效覆盖」。这会在本次连接中启用实体自动同步，同时通过公开设置请求关闭键盘灯光休眠，保护当前同步成功的额度键：通知图案、基础颜色、基础亮度与基础图案都不能覆盖它们。区域重叠时额度优先。位置修改需下次成功同步才切换保留区域。重新连接会关闭固定和实体自动同步；暂停读取后保留最后成功快照。

屏幕仍默认自动刷新，支持 30 秒、1/3/5/10/30 分钟。实体同步仍由用户明确开启，按间隔、变化去重和数据有效性限制发送；固定时可与通知同时更新。读取失败或应用退出后实体灯不会自行熄灭，不能把旧快照当成实时值，请查看最近同步时间。

## 基础区域、通知区域与优先级

显示优先级为 **固定额度区 → 通知区 → 基础区域**。默认开启「独立通知区域」，通知键平时熄灭，出现通知时显示已选图案，四秒后恢复待机；其他区域保留已知底图。通知期间额度若成功更新，恢复时使用最新额度，避免倒退到旧快照。

通知键、通知图案、通知颜色与基础设置分别编辑。点击「应用区域设置」或「应用基础灯效」写入当前区域配置。选键与预览本身不写键盘。默认右侧数字区，提供光框、十字、棋盘及自由绘制。通知至少间隔十秒，密集横幅合并为一次提醒，不累计播放。

RK98 的公开协议只能使用整板固件动态模式，或整板逐键静态配色；尚无已验证的逐帧 RAM 接口。因此固定额度或独立通知开启时，基础区域使用纯色、渐变或**静态雨滴**，没有假装原生动画能在局部继续播放，也没有高频写入可能持久保存的配置。

若要跑马灯：取消固定额度、关闭独立通知、底图选「纯色」，再选择「跑马灯」并应用。当前列出 20 个公开固件模式，包括跑马灯、蛇形追逐、旋转风车、星光等；具体效果仍需这台键盘实测。「星雨（固件星光）」是星光闪烁的模式名称，并非已验证的落雨动画。全局固件模式下，通知会暂用静态颜色，四秒后恢复原模式。固定额度的隔离保证针对本工具的写入；键盘自身快捷键、其他软件、断电及不遵从该设置的固件行为仍可能改变显示。

## 微信等系统横幅 → 键盘（实验）

此前的通知功能只有手动、计时、快捷键及 URL 触发，没有监听其他应用的系统通知，因此微信弹窗不会自动亮灯。0.5 新增通知中心横幅元数据检测：

1. 连接键盘，先应用一次基础灯效作为恢复基准。
2. 在「灯效与通知 → 系统通知 → 键盘」打开「辅助功能授权设置」，允许当前这份 FeralKey。
3. 重新打开工具并连接、应用基础灯效，再开启「监听新出现的系统横幅（实验）」并确认本次范围。此操作会启用独立通知区域。
4. 点击「测试系统横幅」。首次还需允许 FeralKey 自己的通知；两秒后出现本应用的横幅。观察数字区亮四秒后恢复，额度区保持不变。
5. 等十秒以上，用微信收到一条会显示系统横幅的消息。界面应更新「上次检测到横幅」并触发所选图案。重连后需要重新开启监听。

macOS 的公开 UserNotifications API 只提供本应用通知，不能据此订阅微信通知。本版经用户开启后，每 750ms 有界扫描 `com.apple.notificationcenterui` 的公开 Accessibility 界面元素，仅读取角色、子角色、标识符、可见性与层级；不读取标题、正文、AXValue、通知数据库，不申请完全磁盘访问，不截屏。首次扫描忽略现存横幅。不会识别通知来自哪个应用，也不按内容过滤。

这是依赖系统界面结构的实验实现，不是 Apple 保证兼容的全应用通知 API。勿扰模式、辅助功能权限变化、通知中心展开、应用自绘弹窗、系统版本及横幅结构变更都可能导致不触发或误触发。状态中显示识别结果，复杂扫描会跳过，避免把不完整树误判为新通知。代码编译及去重模拟测试通过，不代表这台 Mac 的微信联动已实测成功。

## 更新权限与验证

本地临时签名会随构建改变。若输入监控或辅助功能开关已开但无效，完全退出后移除旧条目，再添加当前 `build/FeralKey.app` 并重开；详见 [权限排查](../PERMISSIONS.md)。应用未修改系统权限数据库，也不会自动授予自身权限。

`scripts/test.sh` 覆盖自选调色板、低额度警示、区域优先级、亮度隔离、通知去重、固定额度下修改基础设置、通知期间额度更新及恢复、显式全局跑马灯模式；HID 全部使用模拟设备。系统横幅检测与实际键盘效果仍需按上述步骤人工验证。
