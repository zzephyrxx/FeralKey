# FeralKey 0.8

## 应用与启用

基础灯效始终提供「应用基础灯效」。无需保留额度区时，呼吸与跑马灯使用键盘原生模式，发送一次后由固件持续播放。代码雨、需要同时显示额度的动画使用独立实时颜色通道；移除了十五秒试播入口。

音乐页提供「启用音乐律动 / 停用音乐律动」，一次操作连接系统音频并开启实体输出，停用时停止采集、恢复基础灯光。进入页面本身不再启动新采集；已经启用的配置可在重启或重连后恢复。默认目标 30 FPS，可选 12 / 20 / 30 FPS。目标值不是实测 USB 吞吐量。

## 闪烁排查与新后端

0.7 提高帧率、减少模式重发后，拥有者仍反馈整板闪烁，故不能把问题归因于帧率低或宣称已修好。原路径反复使用静态逐键配置事务，本版停止把它用于连续动画。

本版参考 [SignalRGB RK84 插件](https://gitlab.com/signalrgb/signal-plugins/-/blob/92dfc19414f3031f65d7e78b50b903908fedda53/Plugins/Royal%20Kludge/RK_84_Keyboard.js) 的另一条路径：七个 65 字节 Feature Report，首包命令为 `0A 07 01 06`，首包载荷 61 字节，后六包各 62 字节，颜色位置为 `1 + bIndex × 3`。与静态保存的 `0A 07 01 03 7E 01` 明确区分。新帧不发模式设置、改键或固件更新命令。

**这是 RK 家族实验通道，尚未验证本机 RK98。** 上游插件列出的 PID 是 RK61/RK84，不含 `00C1`。本机描述符有相应 Report ID 和厂商集合，矩阵索引也能交叉对应，这是实施受控适配的依据，不是成功证明。第一次使用显示专门确认；未确认时不自动使用新指令。不能保证支持、无闪烁、仅写 RAM 或无存储影响。若无响应、闪烁加剧或其他异常，应立即停用并记录现象。

实现上将实时发送移到串行后台队列，包间隔约 1ms；同一设备事务不交错，前一帧未完成时丢弃后续渲染机会，不堆积旧帧。连接/停止会使旧代次失效；失败关闭连接并停止输出。静音/颜色不变时仍保留 250ms 心跳，避免可能的固件超时接管。音量包络放缓衰减，灯柱阈值改成软边缘，减轻画面内容的开关式跳变。

## 两组额度灯独立配置

五小时和每周分别有启用开关及颜色，点击「应用额度灯配置」后一起提交当前选择。可以只开五小时、只开每周，或全部关闭；只检查启用组的数据，缺失的关闭组不阻塞应用。全关无需账号数据，按键回到上次基础底色。首次尚无底色时使用软件中的当前底色建立恢复快照。

每组固定十个槽位：**10%、20%……100%**。默认五小时为 F1–F10，每周为数字行 1–0。每颗键代表一段 10%，不足一段按亮度比例显示。键盘预览直接标注百分比，编辑时先点百分比槽，再点实体按键；重复占用会交换位置，始终保持两组各十键、不重复。

旧版的点击追加顺序仅在升级迁移时按从上到下、从左到右整理，缺失槽位补齐。迁移不视为已应用：升级后需点击一次应用，才恢复新版额度灯。新的逐槽配置按用户指定顺序保存，之后不会再自动重排。

颜色、开关和位置作为草稿自动保存；后台同步始终使用上次成功应用的完整配置，编辑中的变化不会偷偷写入。基础灯光保留已应用额度；「固定额度区」进一步确保音乐和通知也不能覆盖。取消固定后，音乐或重叠通知可临时覆盖，结束回归额度。通知键平时仍参加整体灯光，通知覆盖五秒后恢复。

## 保存与恢复

延续 0.7 的自动保存，新增两组启用状态、已应用额度配置、实时通道确认和音乐启用状态。保存草稿与成功快照分开；恢复时等待启用组的真实有效额度，不使用演示值。完整改键仍不自动重发。

## 验收顺序

1. 完成当前应用的输入监控权限，先常亮选色并点击应用。
2. 关闭周额度，应用额度配置：周额度键应回到底色，五小时保持显示；检查 F1 为 10%、F2 为 20%……F10 为 100%。
3. 改颜色但暂不应用，刷新额度：实体应继续用旧颜色；点击应用后才更新。
4. 先验证原生呼吸/跑马灯。再按需确认实验实时通道，启用音乐；观察新路径是否改善闪烁，停用后应恢复基础灯光。
5. 记录 RK98 的模式、目标 FPS、实际现象及是否有键位偏移。自动化全部使用模拟 HID，不能代替这一步实物验证。
