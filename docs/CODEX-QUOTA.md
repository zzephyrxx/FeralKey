# Codex 额度接入

依据 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 的 `account/rateLimits/read`。不需要逆向账号接口，不需要把 Cookie 或 OAuth 令牌粘贴进FeralKey。本项目没有读取 Codex 的 auth.json、浏览器 Cookie 或聊天记录的代码。

## 复现前提

- 已安装支持 `app-server` 的 Codex CLI，并使用 ChatGPT 账号登录；API Key 登录不提供这里的套餐额度。
- 或拥有可提供该命令的 Codex/ChatGPT 桌面应用内置可执行文件。自动搜索常用路径，找不到时在应用里手动选择。
- 本地登录、代理和网络状态由 Codex 管理。FeralKey复用运行的可执行文件所使用的本机 Codex 登录，不保证和另一台机器或其他独立登录配置是同一账号。

启动一个短生命周期的子进程，通过标准输入输出发送：

```json
{"id":1,"method":"initialize","params":{"clientInfo":{"name":"feralkey","title":"FeralKey","version":"0.8.0"}}}
{"method":"initialized"}
{"id":2,"method":"account/rateLimits/read"}
```

先等初始化成功，再发送后两项。读取完成即关闭子进程，不创建 thread/turn，不调用模型，不消费额度重置券。Codex 自身可能刷新登录状态或写运行日志；FeralKey不保存原始响应、令牌或额度历史。

## 数据规则

- 优先 `rateLimitsByLimitId`，缺失时兼容 `rateLimits`。
- 优先选 `codex` 桶；只有一个桶时选该桶。存在多个不同桶且没有 `codex` 时，让用户选择，不任意合并。
- 按 `windowDurationMins == 300 / 10080` 区分五小时及每周，不假定 primary 永远代表五小时。
- 剩余百分比为 `clamp(100 - usedPercent, 0...100)`。
- 缺失值、缺失重置时间、读取失败、超过两个刷新周期加 30 秒（至少 180 秒）或已跨过重置时间，显示未知；不会把 null 解释成 0，也不会自行推断重置后已满额。
- 默认每 60 秒自动读取，可选 30/60/180/300/600/1800 秒，开关和间隔保存在本机。25 秒超时；失败、取消和退出都会关闭自己启动的子进程。可暂停，不后台常驻服务。
- 演示数据明确标注，不能用于实体同步。

## 从数据到灯条

默认 F1–F10：五小时，绿色；数字行 1–0：每周，蓝色。可在界面重新选择按键，不能重叠。每组固定十个百分比槽，配置后应用再填充，尾段按小数比例调暗；0% 全灭。≤25% 橙色，≤10% 红色。未知仅在屏幕显示灰色，禁止把失效数据发送到实体。

实体可单次同步或由用户开启本次连接的自动同步，使用 Rangoli 的自定义模式 **14** 和 7 个逐键 RGB 报告，共 8 个 65 字节 Feature Report。保留本次应用的基础底图，通知键平时参与整体灯光，不发送改键报告。自动同步只在颜色变化、达到所选间隔且数据有效时写入，未固定时通知期间暂停；固定时保持区域优先并允许与通知同时同步。偏好自动保存，重连后等待有效真实额度恢复；暂停刷新时停止后续自动写入。两组配色、固定设置及硬件限制见 [0.8 功能说明](history/FEATURES-0.8.md)。由于存储机制未知，默认关闭实体自动同步，不进行高频刷新。

键盘显示的是上次成功同步时的快照。应用暂停、网络失效或退出后，它不会自动变灰或清空，请以应用显示的读取时间与发送时间为准。

## 无键盘验证

```sh
./scripts/test.sh
./scripts/quota-smoke.sh          # 模拟额度 → 两组颜色 → 完整报告校验
./scripts/quota-smoke.sh --live   # 真实额度 → 两组颜色 → 完整报告校验
```

两种 smoke 检查均不链接 HID 传输代码，不打开设备，始终 `hardwareReportsSent: 0`。无需等到键盘旁边即可验证软件流程。不要把个人额度输出放入公开仓库。
