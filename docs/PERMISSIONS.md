# 输入监控开关已打开，但连接仍被拒绝

本机排查已确认一种具体情况：系统授权日志对 `local.zephyr.rk98lab` 的 `kTCCServiceListenEvent` 返回 `Failed to match existing code requirement`。保存的旧构建签名与当前应用签名不匹配，系统因此拒绝当前进程。应用路径正确、界面开关显示开启，也不能证明旧签名记录适用于新构建。

当前构建脚本使用 `codesign --sign -` 临时签名，生成的 designated requirement 绑定具体代码哈希。代码变化后，即使应用名称、路径和 bundle ID 保持一致，也可能需要重新授权。参见 [Apple 的代码签名要求说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。

## 恢复当前版本的授权

1. 完全退出 FeralKey（不是只关闭窗口）。
2. 打开「系统设置 → 隐私与安全性 → 输入监控」。
3. 选中 FeralKey，使用 `−` 移除旧条目。
4. 使用 `+` 重新选择当前使用的 `build/FeralKey.app`，并打开开关。文件选择器可按 `⌘⇧G` 输入应用的绝对路径。
5. 重新打开这一份应用，点击连接。

以上只更改 FeralKey 的条目，不需要重置其他应用权限，也不需要关闭系统安全功能。授权必须由用户在系统设置中完成。如果仍失败，应重新检查该进程的权限状态及后续系统日志，不能直接认定为同一个原因。

## 后续开发与分发

开发迭代需要稳定的证书签名身份，并验证新构建满足相同的 designated requirement；保留 bundle ID 不够。正式分发使用 Developer ID 签名和公证。采用这些方式后仍需首次用户授权；不能保证换证书或更改签名要求后授权自动延续。

本次排查仅退出应用并指导更新授权，没有重新构建应用、修改系统授权数据库或向键盘发送配置。恢复授权后，实体连接与灯效仍需分别验证。

## 0.5 新增系统横幅权限

输入监控用于打开键盘控制接口；辅助功能用于用户主动开启的通知中心横幅元数据检测，两者用途不同。微信联动需要在辅助功能中添加当前 FeralKey 并重新开启监听，不需要完全磁盘访问。测试本应用自己的系统横幅还需通知授权。临时签名更新也可能让辅助功能旧条目失效，可同样退出、移除旧条目、添加当前版本并重开。检测依赖系统界面结构，有权限也不保证所有弹窗可识别，详见 [0.5 功能与测试](history/FEATURES-0.5.md)。

## 0.7 统一入口

每页右上角「连接与权限」提供输入监控、辅助功能、系统音频入口与当前应用位置。设置自动保存，权限缺失不会清空选择；授权仍由用户在系统设置完成。自动连接和恢复行为见 [0.7 说明](history/FEATURES-0.7.md)。
