# FeralKey：开源生态、近期高端键盘与玩法调研

调研时间：2026-10-29。范围：RK98（258A:00C1）、Mac、不拆机。本文是调研与产品提案，不代表下述功能已实现。本轮未发送任何键盘配置报告，未安装第三方驱动或更改应用。

## 判断

FeralKey 值得探索的定位是「能随当前应用切换用途、能反馈任务状态的实体工作台」。优先借鉴应用联动、动作编排、状态反馈与可发现的快捷键界面；磁轴行程、Rapid Trigger、8K 无线、OLED 与旋钮是不同层面的硬件能力，不能仅靠软件为这把 RK98 补出来。

## 实时 RGB 的新线索

只读检查了 RK M75 源码，提交 `abf286541b096da2a62360ec7b12035babc007d0`，重点为 `docs/protocol.md`。

其作者记录：单个 RGB 报告带来的颜色约 1 秒后会被固件接管；持续发送可以保持外部控制；在特定 M75 的 Windows 测试中持续到 33 Hz。该现象支持「有临时灯光控制路径」的研究方向，但不能代替芯片闪存写入行为的完整证据，也不能外推到其他型号。

| | 本机 RK98（已枚举） | M75 项目（作者报告） |
|---|---|---|
| VID:PID | 258A:00C1 | 258A:0163 |
| HID usage page / usage | 0001 / 0080 | FF02 / 0001 |
| 灯光 Feature Report ID | 0A | 09 |
| 含 ID 的报告长度 | 65 | 520 |
| 实体持续刷新 | 未验证 | 特定硬件与 Windows 上验证到 33 Hz |

结论：适合借鉴捕获、帧映射、超时接管和限速测试的方法，不适合把 520 字节报告发送到 RK98。RK98 高速刷新前仍需确认其临时数据通道与写入语义。

## 产品提案（以下均为我们的设计建议）

### 1. 数字区成为无屏 Stream Deck

按住一颗闲置功能键，数字区暂时进入动作页：运行任务、截图、专注、窗口布局、播放器、常用快捷指令。松开回到数字输入。Mac 屏幕同步显示一块玻璃浮层，显示每个键当前用途、状态与剩余时间。可以保留数字区日常用途。

推荐先做 6–9 个动作、一个临时层。复杂按住/松开与设备隔离需主机输入处理引擎；先选择一颗主机可观察的键，不能假设键盘原生 Fn 会暴露给 Mac。

### 2. 随应用切换的技能页

切到编辑器，数字区负责测试、运行、格式化、搜索；切到浏览器，变成标签页/阅读/下载操作；切到创作软件，变成时间轴、工具和视图。按住功能键时可看见玻璃浮层帮助，松开消失。

键盘只做一次基础功能键映射，日常应用变化由 Mac 解释，避免切一个窗口就给键盘重写全部映射。需要逐应用的动作适配，不承诺任意软件自动可控。

### 3. 任务状态与电脑状态的灯光语言

开始任务、等待输入、完成、失败对应固定颜色/节奏。可以接本地任务、构建、下载、计时器，或支持 hooks/状态输出的 AI 工具。灯光反映真实状态；不能把发送了「静音」快捷键直接当成已确认静音成功。

第一版优先少量状态变化提醒与屏幕浮层。逐键持续进度条、呼吸动画和系统音频律动需先突破实时 RGB 与写入语义。

### 4. 虚拟旋钮

按住一颗键并移动鼠标，临时将移动量映射为音量、时间轴、缩放或画笔大小，松开恢复鼠标。用屏幕圆环或刻度给出反馈。依赖输入事件处理与目标软件适配；不用在键盘上加物理旋钮。

### 5. 音乐与演奏模式

音乐路线：捕获授权的音频来源，做低/中/高频分区、能量条、专辑色等，等待临时 RGB 通道验证后输出到实物。系统播放音频采样需单独处理平台能力与授权。

演奏路线：将普通按键转成 MIDI 音符、和弦或鼓垫；普通 RK98 没有力度数据，力度由软件设定。实体逐键灯光反馈仍依赖 RGB 验证。小键盘也可作为采样器控制页。

### 6. 自然语言规则工坊

用户描述「编辑器里这排键做测试与调试，浏览器里控制标签页」。生成可检查的配置草案、显示按键效果与冲突、由用户手动应用。AI 参与配置生成，日常按键由本地确定性规则执行。先做好可靠的规则模型，再考虑自然语言入口。

### 更疯狂的第二阶段

- 逐键灯光贪吃蛇、节奏游戏与像素状态板：等待稳定的临时 RGB 流。
- 灯光设备编排：提供适配层，再桥接 OpenRGB 支持的设备；不把跨品牌 SDK 当成 RK98 支持证据。
- 只统计快捷键使用与按键频率的个人配置建议：不记录输入文字，建议由用户审阅后启用。

## 建议讨论顺序

最先讨论「数字区工作台＋应用识别＋玻璃提示浮层」这个完整体验；与此同时独立研究 RK98 的灯光传输。主机端能力不应被 RGB 的未知状态卡住。

接着讨论你真正想每天使用的应用与动作。最后再决定是否需要现成 Karabiner/Companion 桥接，或逐步实现轻量原生输入引擎。不要同时运行多个引擎去接管同一批按键。
