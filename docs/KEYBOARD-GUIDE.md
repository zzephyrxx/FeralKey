# 从自己的键盘开始

FeralKey 0.3 是 macOS 研究预览版。当前写入适配仅限 USB `258A:00C1`（RK98-100KRGB N）。其他键盘可以做只读识别、导出研究包；不会因为品牌同为 RK 或外壳型号相似就允许写入。

## 1. 准备与风险确认

使用闲置、备用或可接受损坏的键盘，保留另一套可用输入设备。不要拆机或刷固件来完成本教程。第一次进入应用「探索向导」需要阅读风险须知并主动勾选，拒绝仍可查看额度与屏幕演示。

风险确认只表示知悉风险，不代表协议经过验证。完整设备写入另有操作范围确认。当前工具无法读取或备份键盘内部灯效、改键配置，导出研究包也不是设备备份。

## 2. 识别，比品牌名称更准确

1. 使用有线模式连接，打开「探索向导 → 扫描键盘」。这一步不发送 Feature Report，也不监听键盘输入。
2. 记录外壳型号、硬件版本（如果有）和应用显示的 VID/PID、连接方式、接口用途、Feature Report 大小。
3. 同一个键盘出现多行接口是正常的；系统名称“Bluetooth Keyboard”也可能对应 USB 连接，以 Transport 为准。
4. 导出研究包，分享前检查产品名称。文件不含序列号、账号、额度或输入内容。多个相同型号实体设备可能合并显示；首轮验证只连接一把待研究键盘。

## 3. 找已有适配

优先找精确设备编号和硬件版本，而不是搜索一个品牌后直接套用数据包。

- [Rangoli](https://github.com/rnayabed/rangoli)：多款 RK 的布局、模式枚举与配置报告。
- [Kludge Knight](https://github.com/vinc3m1/kludgeknight)：可交叉核对 RK 协议；检查它实际支持的型号。
- [OpenRGB](https://openrgb.org/)：检查设备支持情况和平台限制。
- [QMK](https://docs.qmk.fm/)：仅适用于其支持的硬件；不要把“支持改键”理解成“能给任意键盘刷 QMK”。

收集证据时保存项目地址、提交编号、具体源文件、报告长度及命令用途。资料相互矛盾时停止，不自动猜测。比如 RK M75 与本机 RK98 的报告 ID、长度不同，M75 的逐帧灯光命令不能发给 RK98。

## 4. 有适配时的验证顺序

仅当 USB 设备编号、接口用途和报告大小全部匹配，才能尝试本项目 RK98 实验适配：

1. 在系统「隐私与安全性 → 输入监控」中授权应用，退出后重开。
2. 点击连接，先应用一次基础常亮灯效。记录是否真的改变了颜色及亮度。
3. 读取真实 Codex 额度。在额度页面确认两组位置，再「同步一次到键盘」。完整发送 8 个灯光报告，不发送按键映射报告。
4. 观察 F1–F10 与数字行 1–0 是否对应两项额度，其他键灯是否熄灭。检查常用按键仍正常。
5. 在「灯效与通知」应用基础灯效，恢复照明。这恢复的是你指定的新设置，不是键盘原设置。

发生设备断连、颜色错位或行为异常时停止。不要反复点击同步；记录现象与时间，重新连接后根据已知设置决定是否恢复。任何报告发送成功仅代表操作系统接受了请求，不等于实物显示正确。

## 5. 没有适配时怎么办

停在教程和证据整理阶段。可以提交脱敏的研究包、外壳型号、公开资料及观察结果。不要上传官方驱动中的账号、抓包中的私人信息或未经许可的固件文件。

本版不做自动爆破、不批量试命令、不执行 AI 生成的原始报告、不提供固件刷写入口。只存在加密协议、硬件版本不明或没有可靠命令来源时，可以以“不支持”结束。

## 6. 开发者如何接入

参考 `docs/adapters/rk98-258a-00c1.json`。该文件是证据清单，不是可自动执行的插件。新适配需要代码审查与单独测试：

1. **设备匹配**：固定 VID/PID、连接方式、用途与报告长度；同型号多个版本分别匹配。
2. **布局**：物理位置、名称与协议中的 LED 索引分开记录，不能简单用键盘扫描码替代 LED 索引。
3. **能力**：注明整体灯效、逐键静态颜色、临时灯光流分别是否支持，以及确认等级。
4. **编码器**：输入统一的 `[键位: RGB]`，输出经过长度、顺序及命令白名单检查的完整事务。参考 `RKCodec.customLighting`。
5. **设备传输**：只对匹配到的目标接口执行该适配器允许的事务，发送前需要风险确认。不要把新增设备直接放行到 RK98 编码器。
6. **验证**：先使用离线样例验证分包、边界和错误拒绝；再由设备拥有者逐项实物验证。更新证据清单，标注测试的操作系统与硬件版本。

额度读取（`CodexClient`）、归一化（`QuotaSnapshot`）、灯条绘制（`QuotaRenderer`）不依赖具体品牌，可直接复用。当前只有 RK98 传输实现；新增品牌仍需编写适配代码，尚无通用插件加载器。

自动刷新实体灯光必须另行确认临时写入与持久保存机制。静态配色可用不等于允许 30 FPS 刷新，也不等于五分钟保存一次就没有存储寿命风险。
